# Core MVP 审查修复

本次承接 [Core MVP](20261116-Core-MVP实施方案.md) 的审查发现，不增加业务范围、领域状态、数据库结构或公开请求字段。依据为[需求](../../docs/需求说明.md)、[设计](../../docs/设计说明.md)及[测试规范](../../docs/测试/README.md)。此前 135 项通过仅代表当时已有用例，不能覆盖本次已复现的缺陷。

## 实施步骤

1. `infrastructure/windows.py`：Job 缺失不能证明执行树退出；无法证明时保留 RECOVERY_PENDING 与名额。`execution/leases.py`、`runtime.py`：仅在 Supervisor 确认 Job 活动数为零且宿主退出后，在所有权保护下持久保存退出证据；恢复可复用同一 Attempt 的该证据，结果及名额仍由完成事务提交，避免已核验退出后崩溃丢失依据。
2. `execution/leases.py`、`scheduling/runtime.py`：领取、续租、恢复、重试完成及规则物化在取得写事务后读取当前时间；规则候选时间计算在事务内按新时间复核，避免锁等待跨越迟到或租约边界。
3. `application/service.py`：仅 SchedulePatch 的规范化保留字段是否提供，区分省略与显式 null；完整请求仍按约定补默认值。
4. `adapters/fake/host.py`：late_result 按已有 duration_seconds 延迟且忽略取消，产生真实可控的结果。测试以真实 Windows 宿主、SQLite、事件屏障和独立进程句柄验证取消/成功竞争、恢复接管后的旧消息/结果、终态不被覆盖及回执/名额唯一。
