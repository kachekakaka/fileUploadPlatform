# 需求说明

更新日期：2026-11-15。本文是现行产品需求入口，承接[初始任务书](../依据/upload-platform-implementation-taskbook-v1.md)中的目标及已确认调整，供后续具体实施方案使用。以下为初始需求基线，产品功能均尚未实现、尚未验收；文档落地不意味着这些功能已交付。

业务术语见 [CONTEXT](../CONTEXT.md)，组织和实现边界见[设计说明](设计说明.md)，测试设计规则见[测试入口](测试/README.md)。本文件维护业务要求，不安排本轮编码，不把初始批次当成实施授权。

## R01 独立应用与统一入口

提供可独立运行的上传应用，支持 REST API、Python SDK、CLI 和 Web Dashboard；首批目标平台是 Bilibili 和百度网盘。外部录制、剪辑工具可以提交文件和任务、查询进度与结果，不依赖某个旧项目内部接口。

验收目标：相同业务经不同入口得到一致结果；SDK 通过公开 REST 访问；Dashboard 通过 REST/SSE 访问。先形成 Core、API、CLI 的可运行能力，再接真实平台，Dashboard 不阻塞 Core 的初步交付。

## R02 文件交接与归属

- 本地已经生成的成片登记原文件位置，执行时直接读取，不默认复制到平台目录。调用方须保留原件到任务结束；平台不比较提交后是否被修改或替换，不保证内容仍是提交时版本。
- 其他电脑通过网页传入的文件，正常完整接收后才可使用；接收中断、写入失败正常报告和处理，半成品不能标为可用。接收完成与上传到 B 站/网盘成功是两个结果。
- 两种交接都不增加文件内容摘要或额外整文件扫描。保留入口所需的路径、普通文件、大小、类型和访问权限边界；实际读取、接收和上传错误正常处理。远程调用不能借登记接口任意读取服务器路径。
- 一个素材可以被多个任务引用，支持视频、封面、字幕、附件及排列顺序。清理只处理平台拥有且无有效引用的文件，不能删除调用方原件，也不能提前删除其他任务仍需使用的素材。

验收目标：本地原件无默认副本、不因内容变化被额外拒绝；网页未收完不可用于任务；失败可追踪；大文件不整体装入内存；共享素材和原件受保护。取舍理由见 [ADR 0001](adr/0001-reference-local-upload-files.md)。

## R03 任务与重复提交

支持即时或定时提交、查询、列表、取消及允许条件下的重试；任务和每次执行尝试分别留存。用户因网络断开未收到提交回复时，使用同一请求标识重发应返回原资源，不再生成一份任务；相同标识携带不同提交内容时报告冲突。这里针对“同一次请求重发”，不要求读取视频内容来识别文件。

验收目标：重复请求不重复创建任务或规则；重试保留前次执行记录；取消和重试结果与真实执行阶段一致，不能盲目重启远端结果不确定的任务。

## R04 定时与队列

支持一次性、每日、每周和 Cron 规则，使用明确时区；修改规则不改变已经生成的任务。同一规则版本的同一触发点最多生成一个任务。任务不提前执行，重启不丢触发；重试任务须等到指定时间才能再次领取。

错过执行时间时支持立即执行、跳过或过期处理，并限制允许迟到时间。夏令时不存在的当地时刻跳过，重复时刻默认选第一次实际发生的时间。队列默认先进先出，允许有限优先级，避免任务长期被插队。

验收目标：并发调度不重复创建，时区和时间边界明确，重启、错过时间和重复时刻均有可验证结果。

## R05 持久化与并发控制

任务、定时触发、执行尝试、执行资格、事件和结果可在重启后追踪；提供当前结构的空库初始化。多个 Worker 竞争时，同一任务不能重复取得有效执行资格，账号并发名额按配置生效。

验收目标：关键状态和业务约束由实际持久化行为保证，失败提交可回滚，旧执行者不能覆盖新一轮的本地结果。已有业务库不因初始化而被自动删除或重建。数据库升级迁移另待用户安排，见[待办](待办.md)。

## R06 执行监督与恢复

平台跟踪实际上传进程的启动、进度、取消和退出。心跳消失或执行资格过期后，先核对进程与结果，不能直接再传一次。远端可能已经收到文件、但本地无法确认结果时，记录为不确定并提供处置入口，不自动重试。

验收目标：进程异常、超时、迟到结果、取消和重启有明确结论；不会忽略孤儿进程；真实故障场景支持恢复声明。模拟上传可验证核心控制流程，但不替代真实平台上传验收。

## R07 事件、日志与可观察性

可查询任务进度、执行历史、状态变化、Worker 健康和错误；事件断线后可续接，重复投递不能重复产生业务效果。日志不得泄露凭据明文。

验收目标：用户看到的状态、事件和持久记录相互一致；成功结果有对应远端证据，不能仅以接口成功、进程退出或结果文件存在认定上传成功。

## R08 Bilibili

支持账号及凭据管理、身份确认、投稿前业务检查、分片上传、多 P、封面与投稿元数据、最终投稿、BVID/AID 结果确认、进度记录和断点恢复。可选兼容后端不能成为 Core 的必需依赖。

验收目标：在明确指定的测试账号下完成实际投稿并取得有效远端标识；中断可安全处理；最终投稿窗口发生故障时不盲目重复投稿。不因本项的投稿前业务检查重新增加 R02 已取消的本地文件内容扫描。

## R09 百度网盘

支持 OAuth、凭据刷新、身份确认、文件预创建、分片上传及持久进度、远端文件创建、远端结果确认、断点恢复、大文件和文件冲突策略；远端状态不确定时提供处置。

验收目标：普通及大文件实际上传成功，可从已完成部分恢复，远端结果与任务对应，冲突按配置处理。远端结果确认不等于额外扫描本地或网页接收文件；具体平台协议需求在对应实施方案中说明，不在本轮预选算法。

## R10 Dashboard 与运维

Dashboard 提供概览、任务队列与详情、定时规则、账号、素材、Adapter 状态、执行历史、事件、恢复和健康入口。产品化包括认证授权、配置、通知、备份恢复、数据清理、Docker Compose 部署及实际操作文档。默认只监听本机，远程访问须认证。

验收目标：界面与公开接口行为一致；部署后数据可持久保存，备份恢复和清理有实际验证；凭据不进入代码仓库。数据库版本升级仍按单独安排处理。
