# 需求说明

更新日期：2026-11-16。本文是现行产品需求入口，承接[初始任务书](../依据/upload-platform-implementation-taskbook-v1.md)中的目标及已确认调整。Core MVP 已实现 R01 的 REST/CLI、R02 的本地引用、R03—R07 在 Fake 场景中的约定范围；验收证据与限制见[实施结果](../archive/方案/20261116-Core-MVP实施方案.md#产品实施结果)。真实平台、SDK、网页接收、Dashboard、Cron 和完整部署仍待后续实现，不将本地模拟结果视为这些范围的验收。

业务术语见 [CONTEXT](../CONTEXT.md)，组织和实现边界见[设计说明](设计说明.md)，测试设计规则见[测试入口](测试/README.md)。本文件维护业务要求，不安排本轮编码，不把初始批次当成实施授权。

## R01 独立应用与统一入口

提供可独立运行的上传应用，支持 REST API、Python SDK、CLI 和 Web Dashboard；首批目标平台是 Bilibili 和百度网盘。外部录制、剪辑工具可以提交文件和任务、查询进度与结果，不依赖某个旧项目内部接口。

验收目标：相同业务经不同入口得到一致结果；SDK 通过公开 REST 访问；Dashboard 通过 REST/SSE 访问。先形成 Core、API、CLI 的可运行能力，再接真实平台，Dashboard 不阻塞 Core 的初步交付。

## R02 文件交接与归属

- 本地已经生成的成片登记原文件位置，执行时直接读取，不默认复制到平台目录。调用方须保留原件到任务结束；平台不比较提交后是否被修改或替换，不保证内容仍是提交时版本。
- 本地目录入口（2026-11-16 已确认）：普通任务由用户直接指定作品目录，选择立即执行或一次性定时；周期任务在创建规则时指定并保存目录，后续按时间规则执行。无需逐个作品另改目录配置；每个生成的任务保存实际采用的素材引用。确认来源见 [Core MVP 方案 Q2](../archive/方案/20261116-Core-MVP实施方案.md#逐项确认记录)；周期父目录组织、就绪筛选、作品身份及本轮范围统一见 R04。
- 其他电脑通过网页传入的文件，正常完整接收后才可使用；接收中断、写入失败正常报告和处理，半成品不能标为可用。接收完成与上传到 B 站/网盘成功是两个结果。
- 两种交接都不增加文件内容摘要或额外整文件扫描。保留入口所需的路径、普通文件、大小、类型和访问权限边界；实际读取、接收和上传错误正常处理。远程调用不能借登记接口任意读取服务器路径。
- 一个素材可以被多个任务引用，支持视频、封面、字幕、附件及排列顺序。清理只处理平台拥有且无有效引用的文件，不能删除调用方原件，也不能提前删除其他任务仍需使用的素材。

验收目标：本地原件无默认副本、不因内容变化被额外拒绝；网页未收完不可用于任务；失败可追踪；大文件不整体装入内存；共享素材和原件受保护。取舍理由见 [ADR 0001](adr/0001-reference-local-upload-files.md)。

## R03 任务与重复提交

支持即时或定时提交、查询、列表、取消及允许条件下的重试；任务和每次执行尝试分别留存。用户因网络断开未收到提交回复时，使用同一请求标识重发应返回原资源，不再生成一份任务；相同标识携带不同提交内容时报告冲突。这里针对“同一次请求重发”，不要求读取视频内容来识别文件。

投稿元数据（2026-11-16 Q13 已确认）：多 P 投稿共用整组总标题、简介、标签和封面，使用作品默认值及上传单元覆盖值；每个 P 可单独设置分 P 标题，单视频的简介、标签或封面不覆盖整组信息。独立投稿模式下，每个视频仍可覆盖标题、简介、标签和封面。工具在提交前展示最终采用的信息，目标不支持的设置明确报错，不静默丢弃；创建任务后保存独立快照。确认来源见 [Core MVP 方案 Q13](../archive/方案/20261116-Core-MVP实施方案.md#逐项确认记录)，解析边界由[设计 D02](设计说明.md#d02-领域与数据约束)维护。

同编号描述更新（2026-11-16 Q14 已确认）：按固定编号识别作品，不比较该作品的投稿描述是否发生变化，不为此设置冲突提示或要求用户显式确认更新；新任务直接采用本次入口提供或选材读取的当前有效描述。已有任务保留原快照，描述变化本身不使作品成为新作品，也不触发向已提交目标重传。正常 schema、目标能力和路径校验继续执行；此决定针对作品身份，不取消同一请求幂等标识携带不同请求时的冲突规则。确认来源见 [Core MVP 方案 Q14](../archive/方案/20261116-Core-MVP实施方案.md#逐项确认记录)。

入口共用提交记录（2026-11-16 Q15 已确认）：普通手动提交与周期自动提交共用同一份投稿和目标账号的提交记录。手动已提交的投稿，自动任务不再创建副本；自动已提交的投稿，手动入口返回已有任务及其状态，不重复创建。不论既有任务排队、运行、成功或失败，均不因换入口而绕过去重；失败或不确定仍走对应处置流程。显式重新上传及重新安排按下文 Q16，不将重复普通提交隐式视为新一轮投稿。确认来源见 [Core MVP 方案 Q15](../archive/方案/20261116-Core-MVP实施方案.md#逐项确认记录)。

显式再提交（2026-11-16 Q16 已确认）：提供重新上传及重新安排操作，保留作品固定编号、原任务及全部执行历史，使用当前有效描述和新的执行安排创建新任务。仅针对已经结束且结果明确的任务；正在执行或结果不确定时先完成取消或恢复处置，不能借此绕过。普通提交仍返回已有任务，自动任务不会自行开启新一轮；失败自动重试仍属于原任务的 Attempt，不与显式再提交混用。确认来源见 [Core MVP 方案 Q16](../archive/方案/20261116-Core-MVP实施方案.md#逐项确认记录)。

验收目标：重复请求不重复创建任务或规则；重试保留前次执行记录；取消和重试结果与真实执行阶段一致，不能盲目重启远端结果不确定的任务。

取消结果（2026-11-16 Q18 已确认）：尚未领取执行的任务可直接取消，不启动上传；执行中的任务先记录取消请求，确认安全停止后才记为 CANCELLED。已经取得有效成功结果时保留 SUCCEEDED，并记录取消未生效；无法确认远端结果时进入 UNCERTAIN，使用 R06 的人工处置流程。取消与领取、完成必须互斥协调，不能因请求顺序或最后一次写入而同时产生矛盾结论。确认来源见 [Core MVP 方案 Q18](../archive/方案/20261116-Core-MVP实施方案.md#逐项确认记录)。

## R04 定时与队列

目录与重试收尾确认（2026-11-16，已确认）：周期规则指定父目录，仅处理其直接子目录中的作品，每个子目录包含自己的 `upload.yaml` 和素材，不递归发现更深层作品，也不把散放视频自动推断为作品。明确可安全重试的失败默认总共最多执行 3 次（首次加两次重试），两次等待分别为 30 秒、2 分钟，均可配置；等待时间持久保存，重启不提前执行，等待中可取消，耗尽后 FAILED。永久失败和不确定结果不自动重试。来源见 [Core MVP 收尾确认](../archive/方案/20261116-Core-MVP实施方案.md#文档收尾确认)。

支持一次性、每日、每周和 Cron 规则，使用明确时区；修改规则不改变已经生成的任务。同一规则版本的同一触发点最多生成一条触发记录，该轮可按作品及目标展开为多个独立任务。任务不提前执行，重启不丢触发；重试任务须等到指定时间才能再次领取。

一轮多任务（2026-11-16 Q11 已确认）：一次周期触发发现多个符合条件的新作品时，将其展开的任务全部排队，统一关联该轮触发记录，各任务独立记录结果和重试；实际执行仍受账号并发额度限制。一轮没有新作品时可以不生成任务，不能为满足数量假造任务。确认来源见 [Core MVP 方案 Q11](../archive/方案/20261116-Core-MVP实施方案.md#逐项确认记录)；本决定替代原基线“一次触发最多生成一个任务”的限制。

周期目录选材（2026-11-16 已确认）：每次到点只为新作品创建任务，已经排队、执行中或已成功的作品不因下一次触发而重复创建任务；失败按原任务的重试规则处理，结果不确定时不自动重传。确认来源见 [Core MVP 方案 Q3](../archive/方案/20261116-Core-MVP实施方案.md#逐项确认记录)。跨规则与跨目标判定按下文 Q7，目录组织与重试默认值按本节收尾确认。

周期重复判定范围（2026-11-16 Q7 已确认）：同一份投稿发往同一目标平台和账号时，所有周期规则共用提交记录，不能因每日、每周规则重叠而创建第二个任务；不同平台或账号可以分别创建任务。判定按作品内实际展开的投稿逐项进行，不能用作品曾向任意目标提交过就阻止其他目标。已有失败任务仍按原重试规则处理；不通过新增周期任务绕过失败或不确定状态。确认来源见 [Core MVP 方案 Q7](../archive/方案/20261116-Core-MVP实施方案.md#逐项确认记录)。

作品身份（2026-11-16 Q5 已确认）：以保存在 `upload.yaml` 中的固定作品编号识别，由工具自动生成，用户无需手工编写；移动或重命名作品目录不产生新身份，复制目录但保留原编号仍视为同一作品。新作品使用新编号，不通过读取媒体内容生成编号或识别重复。编号的持久化与登记约束见[设计 D03](设计说明.md#d03-文件引用接收与清理)，确认来源见 [Core MVP 方案 Q5](../archive/方案/20261116-Core-MVP实施方案.md#逐项确认记录)。

Core MVP 交付范围（2026-11-16 Q4 已确认）：包含立即执行、一次性定时、每日和每周任务；Cron 留到后续。本轮覆盖固定目录选取新作品、持久化调度记录及重启恢复，具体接口与验收见[来源方案](../archive/方案/20261116-Core-MVP实施方案.md)。本次产品实施授权及结果另记于方案，后续不以范围确认替代实施指令。

作品就绪（2026-11-16 Q6 已确认）：准备方在素材全部准备完成后，通过工具明确标记为可上传，周期任务只选取已标记的新作品。只有编号、描述文件或素材存在不足以表示准备完成；未标记作品留待后续触发处理，不因此记录为已提交。该标记是准备方声明，不增加内容扫描或提交后变化检测，执行时仍正常处理文件缺失和读取失败。确认来源见 [Core MVP 方案 Q6](../archive/方案/20261116-Core-MVP实施方案.md#逐项确认记录)。

周期作品隔离（2026-11-16 Q12 已确认）：同一轮中，某个作品校验或派发失败时记录该作品的错误，不阻止其他正常作品创建任务；失败作品不因这次发现而被标为已提交。修复后可在后续周期重新处理，正常作品已生成的任务不重复创建。此处指任务创建前的作品错误，与已存在上传任务的失败重试分开。确认来源见 [Core MVP 方案 Q12](../archive/方案/20261116-Core-MVP实施方案.md#逐项确认记录)。

错过执行时间时支持立即执行、跳过或过期处理，并限制允许迟到时间。夏令时不存在的当地时刻跳过，重复时刻默认选第一次实际发生的时间。队列默认先进先出，允许有限优先级，避免任务长期被插队。

Core MVP 周期补执行（2026-11-16 Q8 已确认）：每日、每周规则因停机错过时间后，恢复时在允许迟到范围内补执行一轮，处理当时已经就绪且未提交的新作品；错过多次也不按次数重复上传。仍遵循 Q7 的投稿与目标账号去重，不替代已创建任务的重试或恢复流程。周期迟到窗口按下文 Q9，一次性定时按 Q10 分别处理。确认来源见 [Core MVP 方案 Q8](../archive/方案/20261116-Core-MVP实施方案.md#逐项确认记录)。

周期迟到窗口（2026-11-16 Q9 已确认）：默认 24 小时，每条规则可单独调整，从最近一次错过的计划触发时间计算。窗口内补执行一轮；超过窗口记录本次跳过并等待下次计划，不删除作品、不将其标为已提交或已上传，下次仍可选取。确认来源见 [Core MVP 方案 Q9](../archive/方案/20261116-Core-MVP实施方案.md#逐项确认记录)。

一次性定时过期（2026-11-16 Q10 已确认）：错过指定时间后默认允许迟到 24 小时，可为该次安排单独调整；超过窗口仍未开始的任务标为 EXPIRED，不自动上传，保留作品与任务记录，由用户重新安排。该窗口从这次原定执行时间计算，不能因重启而延后；不是已开始上传的运行时限。确认来源见 [Core MVP 方案 Q10](../archive/方案/20261116-Core-MVP实施方案.md#逐项确认记录)。

验收目标：并发调度不重复创建，时区和时间边界明确，重启、错过时间和重复时刻均有可验证结果。

## R05 持久化与并发控制

任务、定时触发、执行尝试、执行资格、事件和结果可在重启后追踪；提供当前结构的空库初始化。多个 Worker 竞争时，同一任务不能重复取得有效执行资格，账号并发名额按配置生效。

验收目标：关键状态和业务约束由实际持久化行为保证，失败提交可回滚，旧执行者不能覆盖新一轮的本地结果。已有业务库不因初始化而被自动删除或重建。数据库升级迁移另待用户安排，见[待办](待办.md)。

## R06 执行监督与恢复

人工处置（2026-11-16 Q17 已确认）：对 UNCERTAIN 提供人工确认成功、确认未成功及保持不确定三种操作，记录核对依据并保留原始异常与执行历史。确认成功须提供结果依据并标明人工确认来源；确认未成功须记录依据且确认旧执行已停止，之后才可显式重新上传；仍不确定时保持状态且不自动重传。本轮仅以 Fake Adapter 验证流程，不将人工输入或模拟证据宣称为已接入真实平台查询。确认来源见 [Core MVP 方案 Q17](../archive/方案/20261116-Core-MVP实施方案.md#逐项确认记录)。

平台跟踪实际上传进程的启动、进度、取消和退出。心跳消失或执行资格过期后，先核对进程与结果，不能直接再传一次。远端可能已经收到文件、但本地无法确认结果时，记录为不确定并提供处置入口，不自动重试。

Core MVP 补充（2026-11-16 已确认）：异常后的旧执行由系统自动检查并尝试收尾，使确认可释放的账号名额恢复服务；不能确认安全释放时保持占用并提示处理。名额释放不代表原上传成功或可重试。确认来源见 [Core MVP 方案 Q1](../archive/方案/20261116-Core-MVP实施方案.md#逐项确认记录)，具体恢复边界由[设计 D05](设计说明.md#d05-worker执行宿主与恢复)维护。

验收目标：进程异常、超时、迟到结果、取消和重启有明确结论；不会忽略孤儿进程；真实故障场景支持恢复声明。模拟上传可验证核心控制流程，但不替代真实平台上传验收。

## R07 事件、日志与可观察性

可查询任务进度、执行历史、状态变化、Worker 健康和错误；事件断线后可续接，重复投递不能重复产生业务效果。日志不得泄露凭据明文。

验收目标：用户看到的状态、事件和持久记录相互一致；成功结果有对应远端证据，不能仅以接口成功、进程退出或结果文件存在认定上传成功。

## R08 Bilibili

支持账号及凭据管理、身份确认、投稿前业务检查、分片上传、多 P、封面与投稿元数据、最终投稿、BVID/AID 结果确认、进度记录和断点恢复。可选兼容后端不能成为 Core 的必需依赖。

验收目标：在明确指定的测试账号下完成实际投稿并取得有效远端标识；中断可安全处理；最终投稿窗口发生故障时不盲目重复投稿。不因本项的投稿前业务检查重新增加 R02 已取消的本地文件内容扫描。

## R09 百度网盘

支持 OAuth、凭据刷新、身份确认、文件预创建、分片上传及持久进度、远端文件创建、远端结果确认、断点恢复、大文件和文件冲突策略；远端状态不确定时提供处置。

验收目标：普通及大文件实际上传成功，可从已完成部分恢复，远端结果与任务对应，冲突按配置处理。远端结果确认不等于额外扫描本地或网页接收文件；具体平台协议需求在对应实施方案中说明，不在本轮预选算法。

## R10 Dashboard 与运维

Dashboard 提供概览、任务队列与详情、定时规则、账号、素材、Adapter 状态、执行历史、事件、恢复和健康入口。产品化包括认证授权、配置、通知、备份恢复、数据清理、Docker Compose 部署及实际操作文档。默认只监听本机，远程访问须认证。

验收目标：界面与公开接口行为一致；部署后数据可持久保存，备份恢复和清理有实际验证；凭据不进入代码仓库。数据库版本升级仍按单独安排处理。
