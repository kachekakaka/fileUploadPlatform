# 测试规范与设计入口

本文件维护测试设计、选测、执行和证据规则。业务预期由[需求说明](../需求说明.md)维护，架构边界见[设计说明](../设计说明.md)，本次验收范围写在对应[实施方案](../方案/README.md)；已存在的环境、夹具和可运行命令只在[测试运行入口](../../tests/README.md)维护。

当前只有规范和初始测试设计，没有产品测试实现或可运行命令。下列要求用于后续建立测试，不是已经通过的测试报告。

## 测试设计怎么写

实施方案至少把本次需求或故障风险对应到：前置条件和输入、实际触发动作、应观察到的结果、适合证明该结果的测试层、所需环境/夹具、必要异常分支及完成条件。说明哪些测试新增、哪些修改、哪些结果可复用，不只列测试名称或文件路径。

业务行为有变化时补能证明变化的自动化测试；修复缺陷应覆盖触发条件和期望结果。纯文档或其他可逆、低影响且没有行为变化的修改做相应静态检查，不为覆盖率数字编写镜像实现的断言。

单个任务的测试设计保留在方案中；有跨任务复用价值的领域、契约、恢复或端到端测试设计可拆成 `docs/测试/主题.md` 并从本入口链接，不同时维护两份完整矩阵。具体测试目录、测试用例代码和运行细节放在 `tests/`。

## 按影响选择范围

- 日常按影响域测试：从改动追踪直接调用方、共享数据、状态、事务、进程和公开契约，选择受影响的行为，不能只选同目录或同名测试。
- 完整测试指约定范围内全部适用的已实现测试。要说明覆盖哪些功能、使用什么环境；“完整本地测试”不能被表述为包含真实平台验收。不默认每次全跑。
- 执行前简述本次影响、准备测试的业务场景、选择的阶段及理由。原任务已覆盖的必要检查可继续，不逐步骤重复申请。
- 公共模块、契约或夹具变化时重新判断影响范围；边界不清先调查，扩大测试时说明理由。不因一次失败自动重跑全部流程。
- 不配置 CI 的工程约定见[根 README](../../README.md)。本地命令在真正实现后登记，不编造尚不存在的检查入口。

## 三个执行阶段

范围和阶段是两回事。以下按交付需要选择，不要求每次全部执行；纯文档修改只做文档检查。

| 阶段 | 要证明的业务结果 | 使用时机 |
| --- | --- | --- |
| 检查本次改动 | 受影响行为及必要错误分支符合约定 | 每次实现或修复，范围随影响选择 |
| 走通本次业务流程 | 从实际入口提交操作，状态、结果和重启后记录能够对应 | 本次形成或改变可运行流程时；Core 开发阶段使用 Fake Adapter |
| 验证真实平台 | 指定账号实际上传后的远端结果，以及涉及的中断、取消或恢复行为 | 开发真实 Adapter 或改变真实上传行为时，按明确账号、数据及操作范围执行 |

Fake Adapter 是可控的测试执行程序，可以制造成功、失败、中断与迟到结果；它不能证明 B 站或网盘真实可用。三阶段是业务说明，不代替测试代码的分层，也不是每个小改动都要走三遍。

## 初始测试设计边界

下表给出应覆盖的风险与观察点；具体用例随对应方案和实现建立，均尚未执行。

| 需求或影响 | 验证载体及应观察的结果 | 关键场景 |
| --- | --- | --- |
| 文档、导航与规则 | 正文、直接引用、路径和变更检查 | 新增、移动、归档后无冲突要求或失效本地链接；不构建或启动产品 |
| R03、R04：状态、时间与调度 | 明确输入和预期、可控时钟；按需要做性质测试 | 非法状态转换、重复请求与冲突、规则版本、时区/夏令时、错过时间、重试到期和队列公平性 |
| R04、R05：事务与并发 | 真实临时 SQLite，观察提交、回滚、重开及多连接/多进程竞争结果 | 不重复生成/领取、账号名额、外键/唯一约束、失败不留半个提交、空库初始化及重复初始化 |
| R05、R06：Worker 与恢复 | 受监督的真实测试子进程，结合事件、结果和持久状态判断 | 远端动作前后崩溃、超时、迟到/无效结果、取消、旧代次写入、租约过期、孤儿进程与 UNCERTAIN 不盲目重试 |
| R01、R03、R07：入口与事件契约 | 经 API/CLI/SDK 实际入口观察业务结果、错误与持久状态，验证契约及消费行为 | 重复提交、错误映射、事件重复投递、断线续接、敏感信息脱敏；SDK 经 REST，不直接读库冒充端到端 |
| R01、R02、R03、R07、R10：Dashboard 与网页操作 | 在实际浏览器中执行受影响操作，核对页面反馈、公开接口结果和后台状态；Core 阶段可使用可控后端与 Fake Adapter | 页面提交和取消任务、进度与结果展示、失败提示、刷新/事件重连后的状态一致性；网页文件接收中断不能在页面误报可用或上传成功 |
| R02：文件交接与清理 | 实际临时文件与受控接收过程，观察可用状态、引用和文件归属 | 本地原件保护、无默认副本、缺失/读写失败、网页中断不标可用、共享引用和清理恢复；不添加内容摘要或提交后变化检测 |
| R08、R09：真实平台 | 指定账号、媒体和明确操作范围，核对远端结果和恢复证据 | 真实上传、分片中断、最终提交结果不确定、取消及恢复；Fake 成功不能替代该结果 |
| R10：部署与产品化 | 相应产物的构建、启动、持久数据、访问边界及相关业务检查 | 配置、认证、容器重启、备份恢复和清理；构建成功不等于业务通过 |

后续测试可按 `unit / integration / contract / recovery / e2e` 组织，随真实用例建立。一个断言放在能直接证明它的层面，不在每层机械复制全部故障；纯 Repository Mock 不能替代实际事务验证，声称恢复能力必须有对应故障证据。

涉及网页行为时，方案列出用户在页面上的操作、预期反馈及与后台结果的核对方法；仅接口测试通过不能替代相应网页验收。按本次影响选择场景，不要求每次跑完整个 Dashboard，也不因网页测试自动开展真实平台上传。浏览器工具和用例随对应实现方案确定，本轮仅约定验证边界。

源码字符串、函数名出现次数等只能辅助结构检查。例如“源码里有重试函数”不能证明失败后按时重试；应触发失败并观察后续任务、尝试和持久状态。同样，接口成功、退出码正常或结果文件存在不能单独证明上传成功。

## 数据、进程与环境隔离

使用任务专属的新测试轮次，日志、样本和详细结果放在[根 README](../../README.md)约定的仓外临时目录；可提交的合成最小夹具按运行入口登记。纯文档检查不强制生成独立报告，范围与结果按下文记录在方案或只读审查的交付摘要中。

测试不得默认使用真实凭据、旧业务库或调用方原件。真实平台账号、数据及操作范围沿用对应任务的明确授权，不将普通本地测试自动扩大为真实投稿。既有授权覆盖的工作无需重复询问。

只清理本轮拥有且允许清理的对象；不按进程名批量结束服务，不清空未知目录。保留正常退出、故障注入和失败后强制回收的区别；依靠强杀收尾不能记成正常退出通过。

## 失败、结果复用与停止条件

失败先区分产品行为、测试工具/夹具和环境前提。前置失败后的依赖步骤记“未执行”；不依赖失败条件且隔离仍可信的检查可以继续。工具修复不能降低原验收标准，不以反复重试抹掉失败现场。

复用结果时核对相关源码及调用链、测试与夹具、配置、依赖和环境仍适用，保留原证据入口和本次复用理由。新增变化使哪项结论失效，就补哪部分；必要检查满足且没有未解决疑点即停止，不反复扩大或重跑。

必要验收失败或被环境阻断时，说明差什么、如何补验，方案不能标为已完成。明确不在范围内的测试说明未执行原因及对结论的影响，不冒充缺陷，也不冒充通过。

## 证据和交付结果

结果区分通过、失败、跳过、未执行、环境阻断；保留命令或操作、版本/工作树状态、环境和依赖、实际覆盖范围、断言结果、未覆盖项及影响。运行日志或截图不能只有路径而没有结果说明。旧成功不能覆盖本次失败；真实上传或持续运行仅报告实际覆盖的账号、操作和时间窗口。

普通文档任务直接在对应方案的结果部分记录检查范围、方法、结果及限制，并随方案归档；只读审查在交付摘要列结果即可。不为同一次文档整理再建立独立验证摘要或确认索引。

只有报告需要跨方案复用、内容较多需独立评审，或用户明确要求独立交付时，才在 `docs/测试/报告/YYYYMMDD-主题.md` 保存独立验证报告，并从本入口或关联方案导航；没有实际内容时不预建目录。方案只链接报告和结论，不重复保存全文。报告注明日期、关联需求/方案、上述执行信息和可定位的原始证据位置，保留历史结论；正文及报告的合并、移动遵循[文档规范](../README.md)。完整日志、大文件和敏感材料留仓外，摘要不复制凭据；不另建全局测试台账。

长期验证方法更新到本目录，实际命令/夹具更新到 `tests/README.md`，历史证据保留当时结论。文档静态检查不等于 JSON Schema/OpenAPI 规范验证、SQLite 约束验证、构建或真实平台验收；原始候选资料不会因链接检查通过而冻结。
